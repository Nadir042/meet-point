# MeetPoint Demo

基于 `G18 neXus 团队_MeetPoint_SRS_V1.1-1.pdf` 的初始化交互原型。响应式 H5 页面，原生 HTML / CSS / JavaScript，无第三方运行时依赖。

## 启动

需要 Node.js 18 或更新版本。在此目录执行：

```powershell
node server.js
```

浏览器打开 **http://localhost:3000**。按 `Ctrl+C` 停止服务。也可执行 `npm.cmd start`；无需 `npm install`。

没有 Node.js 时，可直接双击 `index.html` 体验基本操作。推荐通过本地服务访问，浏览器对文件协议的存储和剪贴板支持可能不同。端口被占用时，在 PowerShell 中执行：

```powershell
$env:PORT = "3001"
node server.js
```

## 三分钟演示

1. 首页自动加载一个四人示例活动，已有两位成员投票。
2. 点击候选卡片的“评分依据与路线比较”，查看评分维度和全员预计耗时。
3. 用“小林”投一票；通过右上角切换为“一诺”完成最后一票。
4. 切回发起者“小林”，点击“全员投票后确认结果”，确认集合点并打开高德导航。
5. “我的活动 → 新建示例活动”可再次演示暂停、恢复、需求修改和重新推荐。

从零创建：点击“创建活动”，填写活动名称、昵称与类型；保存自己的出行需求，通过“邀请伙伴 → 添加演示成员”加入其他成员并填写需求。至少两人就绪后，切回发起者生成推荐，开始投票。

## 明确的演示边界

- **不是完整生产系统**：无服务器、数据库、真实登录或多人实时同步。右上角身份切换是演示工具，不是认证机制。邀请码只在已有活动的同一浏览器中有效。
- **没有地图 API**：使用上海示例地点、近似坐标和自绘示意图，非真实地图。路线按直线距离与交通速度参数模拟，不能作为实际出行依据。
- **评分为可替换的演示模型**：公平性 35%、整体耗时 30%、偏好 20%、交通便利 15%。每维 0—10 分；详细公式在界面和 `core.js` 中可查看。示例地点预算不是实际消费报价，交通费用统一显示“未知”，不计入综合分。
- **浏览器本地存储**：刷新可恢复。游客 24 小时 / 账号 7 天恢复期限尚未实现，本地数据不自动过期。浏览器关闭时不会运行计票，重开页面后按保存的截止时间补算。
- **隐私是界面层演示**：其他成员页面隐藏具体出发地，但所有演示数据仍在浏览器存储中。真实权限控制与隐私过滤必须在后端执行。
- 真实地图搜索、定位授权、地图异常重试、账号注册登录、管理员反馈处理、HTTPS 部署、50 人并发与可用率验收尚未接入或测试。
- 导航按钮会把当前示例出发地、目的地传入高德外部导航链接。第三方实际路线及客户端兼容性须在联网环境验收。

后续建议按顺序接入：后端身份与活动 API → 数据库与服务端计票 → 高德地点及路线适配 → 多人同步 → 真实恢复期限及反馈管理。核心状态规则已与 UI 分离，可作为后续实现的参考。
