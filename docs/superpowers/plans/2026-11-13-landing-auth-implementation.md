# Landing Page 与登录入口实施计划

## 成功标准

- 未登录默认显示 Landing Page；账号登录后进入现有工作台。
- PPT 人物原稿作为首屏视觉中心，抽象地图、毛玻璃和动效不影响可读性。
- 登录与注册在同一 `dialog` 中切换，提交沿用现有账号接口。
- 桌面 1440px 和手机 390px 无横向溢出，键盘焦点和降级行为可用。
- 现有工作台和 Apifox 业务请求保持不变。

## 实施步骤

1. **落地素材与视图边界**
   - 从 PPT 已提取 PNG 复制到 `assets/landing-people.png`。
   - 在 `app.js` 增加 `landing` / `workspace` 顶层视图状态。
   - 验证：未登录初始化不会渲染工作台；登录态仍可直达工作台。

2. **构建 Landing 结构**
   - 在 `app.js` 增加语义化导航、Hero、了解区、三步指南和页尾。
   - 添加登录、注册、开始使用、我的活动、锚点滚动和移动菜单动作。
   - 验证：所有入口行为与设计规格一致。

3. **统一认证弹窗体验**
   - 复用当前 `dialog`，增加认证弹窗标识、模式说明、提交中状态和行内错误。
   - 登录/注册成功后切换到工作台；退出后回到 Landing。
   - 验证：接口路径和请求字段不变，错误不再只依赖 toast。

4. **完成视觉与响应式样式**
   - 在 `layout.css` 增加 Landing 专属样式、PPT 素材裁切、SVG 路网、毛玻璃和响应式规则。
   - 在 `styles.css` 完善选择、焦点、对话框和 reduced-motion 行为。
   - 验证：1440px、900px、390px 下层级、点击区域和溢出正确。

5. **回归与视觉检查**
   - 运行语法检查和现有测试，单独记录基线失败。
   - 启动本地服务，检查 Landing、移动菜单、登录/注册切换和工作台切换。
   - 保存桌面与手机截图并运行 Impeccable detector。

## 预计变更文件

- `assets/landing-people.png`
- `app.js`
- `layout.css`
- `styles.css`（仅必要的全局焦点/对话框状态）
- `docs/superpowers/plans/2026-11-13-landing-auth-implementation.md`

## 明确不触碰

- 工作台内部页面结构和业务接口。
- 地图、推荐、投票和成员需求的数据模型。
- 服务端账号协议及 Apifox 字段。
