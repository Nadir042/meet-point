# 活动页面上下级实施计划

设计依据：`docs/superpowers/specs/2026-11-17-activity-page-hierarchy-design.md`

## 任务 1：确定活动默认子页面

**修改：** `core.js`、`tests/core.test.js`

- 增加可测试的活动详情默认页面判断。
- 需求未完成返回成员需求页，需求完成返回集合点页。

**验证：** `node --test tests/core.test.js`

## 任务 2：重构顶层与活动详情导航

**修改：** `app.js`

- 活动目录页的胶囊导航保留“我的活动、意见反馈”，日历继续作为独立常驻入口。
- 活动详情页将胶囊导航实时替换为“返回活动目录、成员与需求、集合点推荐、意见反馈”。
- 删除正文顶部重复的返回入口和子页面切换器。
- 保留需求页和集合点页现有标题及内容文案。
- 打开、创建、加入和恢复活动时使用默认子页面判断。

**验证：** `node --check app.js`

## 任务 3：适配桌面与手机布局

**修改：** `layout.css`

- 调整桌面胶囊宽度，使四个入口保持清晰、可点击且当前页高亮正确。
- 手机端继续使用现有折叠菜单，并根据目录层级或活动详情层级实时切换同一组导航项。
- 手机端活动详情菜单将“返回活动目录”放在第一项，不在正文额外增加重复按钮。
- 修复手机断点隐藏个人账号按钮的问题，并将其收敛为常驻头像按钮。

**验证：** 检查约 1440px、390px 和 360px 视口。

- 验证需求与集合点切换、返回我的活动及活动切换。

- 运行 `npm run check`、`npm test` 和界面检测。
