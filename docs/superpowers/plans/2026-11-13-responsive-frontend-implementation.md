# MeetPoint 响应式前端实施计划

设计依据：`docs/superpowers/specs/2026-11-13-responsive-frontend-redesign.md`  
视觉依据：`DESIGN.md`  
工作分支：`zqz/frontend`

## 验收总则

- 每一步只改与当前目标直接相关的文件。
- 每一步完成后运行针对性检查，并在约 1440px 桌面与 390px 手机视口观察实际页面。
- 不掩盖 PR #15 已存在的测试与语法检查问题；本轮不得新增失败。
- 未获得后端接口或高德配置时，显示真实受限状态，不伪造数据。

## 任务 1：建立视觉变量和页面外壳

**修改文件：** `styles.css`、`layout.css`  
**必要时修改：** `index.html`

1. 将现有绿色主色体系调整为 `DESIGN.md` 的米白、暖黑、珊瑚橙和路线辅助色。
2. 统一正文、标题、标签、按钮、输入框、卡片、焦点和禁用状态。
3. 将正文最小可读字号提高，移除移动端用于挤压内容的 8–10px 核心文字规则。
4. 保留现有 DOM 和功能，不在本任务调整业务逻辑。
5. 验证顶部导航、页面标题、按钮层级和卡片在桌面与手机正常显示。

**验证：**

- `node --check app.js`
- 浏览器检查 1440px、1024px、390px、360px。
- 键盘 Tab 检查导航与主按钮焦点。

## 任务 2：活动概览与创建/加入流程

**修改文件：** `app.js`、`styles.css`、`layout.css`  
**测试文件：** 仅在交互逻辑变化时更新相应测试。

1. 简化概览页标题、活动卡片和操作层级。
2. 保证每屏只有一个主要珊瑚橙行动。
3. 重排创建、加入和身份弹窗，使手机键盘弹出时仍可操作。
4. 保持邀请码、身份切换、活动状态和示例数据提示的现有语义。

**验证：**

- 创建活动和邀请码加入的人工流程。
- 长活动名、长昵称和错误输入。
- 桌面弹窗、390px 手机弹窗及键盘焦点顺序。

## 任务 3：成员需求表单与接口契约

**修改文件：** `app.js`、`styles.css`、`layout.css`  
**测试文件：** `tests/shared.test.js` 或新增最小前端契约测试。

1. 保留地点搜索结果的可见选择状态。
2. 核对保存请求使用 `PUT /api/activities/:id/requirements`，并与 Apifox 字段一致。
3. 增加“使用当前位置”入口；仅在用户点击并授权后调用定位与 `/locations/reverse`。
4. 保留隐私开关说明，确保未公开地点不会在其他成员视角显示。
5. 保存中禁用重复提交，成功与失败均给出明确反馈。

**验证：**

- `node --test tests/shared.test.js`
- 手动验证搜索地点、选择结果、保存、拒绝定位和定位失败。
- 检查 390px 下输入框、搜索结果和提交按钮可见。

## 任务 4：推荐分组、地图和候选详情

**修改文件：** `app.js`、`styles.css`、`layout.css`  
**可能修改：** `amap.js`、`index.html`  
**测试文件：** 与地图数据转换相关的现有或新增最小测试。

1. 将三类推荐切换器改为清晰可读的响应式控件。
2. 候选地点按名称、排名、时间、公平度、费用状态、理由的顺序呈现。
3. 接入真实高德地图容器与标记；前端 Key 通过运行环境提供，不写入仓库。
4. 桌面详情使用浮层，手机详情使用文档流或底部面板，不能遮挡投票主操作。
5. 未配置地图时显示可恢复说明，不继续展示为真实地图的 SVG 示意图。

**验证：**

- 地图正常、无 Key、配额错误、无路线和空候选五种状态。
- 三类推荐的键盘切换和手机触控。
- 长地点名、未知费用和多条路线。

## 任务 5：投票、结果和导航

**修改文件：** `app.js`、`styles.css`、`layout.css`

1. 明确未投、已投、改票、截止、平票、零票和已确认状态。
2. 将投票主操作与当前候选详情绑定，避免误投。
3. 结果页突出最终地点、关键路线信息和“打开高德导航”。
4. C 的投票历史接口未完成时不加入假历史；只保留未来接入位置。

**验证：**

- `node --test tests/core.test.js`
- 手动验证投票、改票、全员投票后确认、零票重开和导航链接。
- 验证手机底部操作不会被浏览器工具栏遮挡。

## 任务 6：错误分类与恢复

**修改文件：** `app.js`  
**可能修改：** `styles.css`、`layout.css`  
**测试文件：** 新增最小错误映射测试或在现有测试中覆盖。

1. 将超时、配额不足、路线不可用、无结果、鉴权失败和普通网络失败映射为不同文案。
2. 每类错误提供合适动作：重试、修改需求、重新授权或返回。
3. 错误后保留用户已填写内容和当前活动上下文。
4. 错误提示使用 `role="alert"` 或状态区域，保持键盘与屏幕阅读器可感知。

**验证：**

- 针对性自动测试。
- 浏览器中模拟断网、超时和无结果。

## 任务 7：完整响应式与回归验收

**修改文件：** 只修复验收中发现且属于本轮范围的问题。

1. 运行完整测试并记录 PR #15 基线失败。
2. 修复 `npm run check` 对不存在的 `scripts/verify-map.js` 的引用，或补齐仓库实际需要的验证脚本；不伪造通过结果。
3. 在 1440px、1024px、390px、360px 走通完整用户故事。
4. 检查键盘、触控、长文本、文字放大、加载、空状态和错误恢复。
5. 审查最终差异，确认每个修改都能追溯到设计规格。

**最终验证：**

- `npm test`
- `npm run check`
- 桌面与手机完整人工流程。
- Git 差异中不包含密钥、临时文件或无关重构。

## 实施节奏

采用三轮完整体验交付：

1. **第一轮：**任务 1–3，完成全局视觉、导航与概览、创建/加入弹窗、需求表单和相关接口契约。
2. **第二轮：**任务 4–5，完成真实地图承载、三类推荐、候选详情、投票、结果和导航。
3. **第三轮：**任务 6–7，完成错误恢复、跨尺寸验收、测试与最终清理。

每轮结束时都同时展示桌面与手机实际效果，再依据用户反馈做小范围调整。若某项受后端接口、地图 Key 或外部服务阻塞，将明确标记并继续完成同轮中不依赖该阻塞项的部分。
