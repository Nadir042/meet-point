# MeetPoint 高德静态地图与导航设计

日期：2026-11-13  
状态：待用户复核

## 目标

在工作台内直接显示包含真实 Top3 候选地点的高德静态地图，并在用户选择最终地点后跳转高德地图完成导航。实现应满足 SRS 对真实地点、地图展示、外部导航、隐私、异常反馈和响应式布局的要求。

本功能不嵌入可拖动的动态地图，不在 MeetPoint 内实现实时导航，也不引入 OSM。

## SRS 对应

- FR-10：展示候选地点名称、地图位置、评分来源和成员出行成本。
- FR-16：最终地点确定后跳转第三方地图导航。
- FR-18：使用地图服务获得地点与路线信息。
- FR-24：地图服务异常时提示原因并允许重试。
- NFR-07：地图调用失败后 5 秒内反馈异常并提供重试入口。
- NFR-08、NFR-09：不向其他成员展示未授权公开的精确出发地。
- NFR-11、NFR-12：兼容指定手机与桌面浏览器并保持响应式布局。

## 架构

### 后端

新增受控的静态地图图片接口。前端只提交活动标识，后端从活动当前推荐结果读取真实 POI 坐标，构造高德静态地图请求，并将图片响应返回给前端。

高德 Web 服务 Key 仅从服务端环境变量 `AMAP_KEY` 读取。前端 HTML、JavaScript、图片地址、错误信息和日志中均不得出现 Key。

后端按“候选 POI ID/坐标 + 图片尺寸”生成缓存键。相同推荐结果复用缓存，避免每次刷新重复消耗高德配额。推荐结果改变时自然生成新的缓存项。

### 前端

现有地图面板继续保留在工作台原位置，只将 SVG 示意图替换为静态地图图片。候选列表仍由 MeetPoint 自己渲染，负责展示评分、时间和费用；静态地图只承担真实地理位置展示。

地图中最多标记 Top3，分别标记为 1、2、3。最终地点确定后突出对应候选，并显示“在高德中导航”。

## 数据流

1. 后端通过现有高德搜索与路线服务生成 Top3，保存 POI 名称、ID、经纬度和路线摘要。
2. 前端请求当前活动的静态地图图片。
3. 后端校验活动访问权限，从活动数据读取当前候选，构造高德静态地图参数。
4. 后端在 5 秒超时内取得图片，校验响应类型后缓存并返回。
5. 前端显示图片、候选卡和地图说明。
6. 最终地点确定后，用户点击导航按钮，使用原始坐标和地点名称打开高德 URI。

前端不得通过查询参数自行传入任意坐标，防止绕过活动权限或滥用后端地图代理。

## 视觉与交互

- 地图卡片沿用工作台的圆角、米色和毛玻璃视觉。
- 地图图片采用轻度降饱和处理，候选标记保持可识别，不施加导致道路与文字不可读的重滤镜。
- 标题使用“候选地点分布”，说明文字使用“地图与路线信息由高德提供”。
- 加载时显示固定比例骨架，避免页面跳动。
- 地图图片本身不承担主要点击操作；候选卡负责切换详情，导航按钮负责跳转。
- 手机端地图全宽显示，桌面端保持现有地图与候选信息组合，不改变已经确认的工作台结构。

## 隐私

- 静态地图默认只标记 Top3 候选地点，不标记成员出发地。
- 成员路线时间由后端计算后以文字展示，不把隐藏成员坐标发送给其他客户端。
- 当前成员发起导航时，只在其本地导航 URI 中使用本人出发地；其他成员无法取得该坐标。

## 错误处理

- 未配置 `AMAP_KEY`：返回可识别的地图配置错误，页面显示降级卡片。
- 高德超时：5 秒内终止请求，页面显示“地图加载超时”和“重新加载”。
- 配额、鉴权或服务异常：后端返回统一错误码，不透传 Key 或高德原始敏感信息。
- 无有效候选：页面显示“生成推荐后将在这里展示地点分布”。
- 图片加载失败：候选文字信息继续可用，不阻断投票和结果查看。
- 导航弹窗被浏览器拦截：保留普通链接供用户再次点击。

## 部署与申请

1. 开发环境继续使用高德 Web 服务 Key，通过本地环境变量注入。
2. 正式上线前重新生成曾在聊天或截图中暴露的 Key。
3. 在高德控制台确认静态地图、搜索和路线规划的实际免费月配额。
4. 在部署平台配置 `AMAP_KEY`，不写入 Git 或公开前端变量。
5. 站点与后端统一使用 HTTPS。
6. 对静态地图响应启用短期服务端缓存，并记录调用失败率；不记录完整 Key。

本方案不需要申请 Web端（JS API）Key或安全密钥。

## 验收标准

1. 工作台显示来自高德的真实静态地图，不再显示“非真实地图”。
2. 地图准确包含当前 Top3 的 1、2、3 标记，名称和坐标均来自推荐结果。
3. 前端源代码和网络中的公开图片 URL不包含 `AMAP_KEY`。
4. 相同 Top3 的重复请求能命中缓存，不重复调用高德。
5. 高德异常或超时后 5 秒内显示错误与重试入口。
6. 地图失败时，候选列表、评分、投票和导航结果页的其他功能仍可使用。
7. 最终地点的导航按钮能在手机和桌面浏览器中打开正确的高德地点或导航页面。
8. 微信内置浏览器、iOS Safari、Android Chrome、桌面 Chrome/Edge 均无布局遮挡或横向溢出。

## 验证

- 单元测试静态地图参数生成、缓存键、访问控制和导航 URI。
- 接口测试正常图片、空候选、超时、鉴权失败、配额失败和非图片响应。
- 验证不同成员无法通过接口取得隐藏出发地。
- 使用 1、2、3 个候选分别检查地图范围与标记。
- 在常见手机和桌面尺寸检查加载、失败、重试和导航跳转。
