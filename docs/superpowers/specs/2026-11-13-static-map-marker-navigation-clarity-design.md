# MeetPoint 静态地图标记与导航清晰度设计

日期：2026-11-13  
状态：待用户复核

## 目标

在不申请高德 Web 端 JS API Key、继续使用静态地图的前提下，提高候选地点标记和导航入口的辨识度，并确保导航按钮真实打开高德路线。

本次不实现地图拖动、缩放或点击地图图片中的标记；这些能力仍需要交互式地图 API。

## 地图标记

- 高德静态地图请求使用 `scale=2` 输出高清图片。
- 标记尺寸从 `mid` 调整为 `large`。
- 标记统一使用 MeetPoint 橙色，并以高对比白色显示 `1`、`2`、`3`。
- 三个编号严格对应当前推荐分组的候选顺序。
- 地图图片继续保持轻度降饱和，但不得降低道路名称和标记的可读性。
- 手机与桌面端继续使用同一静态地图接口和现有响应式布局。

## 候选列表联动

- 地图旁候选列表使用与地图一致的圆形 `1`、`2`、`3` 编号。
- 当前选中的候选编号增加深色外圈、橙色填充和轻微放大。
- 点击候选列表或地图上方的地点快捷按钮，继续打开现有地点详情面板。
- 不宣称静态地图图片中的标记可点击，避免形成错误预期。

## 导航入口

- 新增统一的导航 SVG 图标，使用明确的定位箭头轮廓，不再使用普通右箭头代替导航含义。
- 最终结果区域的主按钮文案改为“在高德地图中打开路线”。
- 地点详情中的导航按钮使用相同图标与文案。
- 按钮保持真实 `<button>` 操作，并在用户点击事件内同步调用 `window.open`，降低弹窗拦截概率。
- 导航参数继续包含本人出发地、最终地点、交通方式、`coordinate=gaode` 与来源 `MeetPoint`。
- 成功点击后真实打开高德 URI；手机浏览器由高德页面决定是否唤起 App，桌面端打开高德网页。

## 跳转失败处理

- 若尚未确定最终地点或本人没有填写出发地，保留现有可操作错误提示。
- 若 `window.open` 返回空值，显示“浏览器阻止了新窗口”，并弹出包含普通高德链接的确认面板，用户可再次点击。
- 普通链接使用 `target="_blank"`、`rel="noopener noreferrer"`，且地址由程序生成，不接受用户输入 URL。
- 不在 MeetPoint 内伪造导航页面，也不承诺第三方高德页面的视觉样式。

## 缓存

静态地图缓存键加入图片规格版本。现有缓存不能继续复用旧的 `scale=1`、`mid` 标记图片，避免部署后仍显示旧标记。

## 验收标准

1. 地图接口请求使用 `scale=2` 和 `large` 标记。
2. 地图上的三个候选标记清晰显示 `1`、`2`、`3`，与候选列表顺序一致。
3. 候选列表选中状态在米色、橙粉色背景上均清晰可辨。
4. 两处导航入口均显示统一导航图标和“在高德地图中打开路线”。
5. 点击导航按钮后真实打开包含正确起点、终点和交通方式的高德 URI。
6. 浏览器阻止新窗口时，页面出现可再次点击的高德普通链接。
7. 地图加载失败时仍保留候选列表和导航入口。
8. 原有静态地图访问控制、Key 隐藏、缓存、投票和隐私测试继续通过。

## 验证

- 单元测试静态地图的 `scale`、标记尺寸、颜色、编号和缓存版本。
- 单元测试不同交通方式生成的高德导航 URI。
- 模拟 `window.open` 成功与失败两种情况。
- 使用全量演示账号检查三个推荐分组及已完成活动。
- 在手机和桌面尺寸检查标记、候选编号、导航按钮及失败回退面板。
