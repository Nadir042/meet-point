# 出行需求与活动偏好多选设计

## 目标

允许成员选择多种可接受的交通方式和多个活动偏好。推荐时为每位成员、每个候选地点计算全部所选交通方式，并采用耗时最短的有效路线。

## 表单交互

- 交通方式与活动偏好由单选下拉框改为可多选的复选选项，均至少选择一项。
- 活动偏好中的“不限”与其他选项互斥；选择“不限”会清除其他项，选择具体选项会取消“不限”。
- “其他”可与具体偏好同时选择，但必须填写 1—20 个字的真实需求。
- 编辑需求时回显所有已选项及自定义需求。
- 保存未完成表单时继续使用现有逐字段标志和动效。

## 数据与接口兼容

- 成员新增 `modes` 和 `preferences` 数组作为多选数据。
- `PUT /api/activities/:id/requirements` 接受 `modes`、`preferences` 和 `preferenceDetail`。
- 继续接受旧的 `mode`、`preference` 字段，并在迁移或读取时转换为单元素数组。
- 为兼容现有页面和旧客户端，投影中暂时保留 `mode`、`preference`，值取数组第一项；新逻辑统一读取数组。
- 旧活动无需重新填写即可继续使用。

## 推荐规则

- 对每个“成员 × 候选地点 × 已选交通方式”请求真实路线，保持现有并发限制。
- 同一成员到同一候选地点采用耗时最短的有效路线，候选结果记录实际采用的 `mode`。
- 某一种交通方式失败时继续使用其他有效方式；只有成员的所有已选方式都不可用时，该候选才视为路线不完整。
- 地点匹配成员任一所选偏好即获得匹配分；“不限”继续使用地点评分。
- 地点搜索关键词合并所有成员的具体偏好并去重。
- 打开高德导航时使用候选结果中为当前成员选出的实际交通方式。

## 范围

- 修改需求表单、成员展示、数据迁移、共享接口、演示推荐、真实高德推荐和导航方式。
- 不修改活动类型列表、地图展示结构、投票规则或页面标题。

## 验收标准

1. 交通方式和活动偏好都能多选、取消并正确回显。
2. “不限”与具体偏好不能同时保存，“其他”必须保存真实填写内容。
3. 旧单选活动能正常读取、编辑、推荐和投票。
4. 多交通方式推荐采用耗时最短的有效路线，并展示实际采用方式。
5. 单一路线失败不会导致其他可用交通方式被丢弃。
6. 接口、核心逻辑和完整共享流程测试通过。
