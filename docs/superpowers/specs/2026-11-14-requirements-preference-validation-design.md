# 出行需求偏好与校验反馈设计

## 目标

调整“我的出行需求”表单，使活动偏好按活动类型展示确认后的选项，支持最多 20 个字的自定义偏好，并在提交不完整数据时逐字段显示清晰的动效警示。线上当前位置功能因当前站点使用 HTTP 暂不可用，保留入口并给出明确说明。

## 活动偏好

活动类型继续保留“聚餐”“休闲娱乐”“线下会面”。各类型允许的偏好如下：

- 聚餐：不限、火锅、烧烤、中餐、西餐、咖啡甜品、其他。
- 休闲娱乐：不限、KTV、桌游、电影院、公园、商场、剧本杀、密室逃脱、美甲、手工、写真、其他。
- 线下会面：不限、学习讨论、工作交流、朋友会面、逛街、其他。

选择“其他”时显示文本输入框，要求填写 1—20 个字。预设偏好继续通过现有 `preference` 字段提交；自定义偏好同时提交明确的“其他”选择和详细内容，服务端负责长度及所属活动类型校验。成员列表显示最终有效偏好文字，推荐搜索使用自定义内容。

## 表单校验反馈

点击“保存我的需求”时检查出发地、交通方式、活动偏好、自定义偏好内容和预算。每个无效字段的标题前显示警示图标，字段容器进入错误状态并播放一次短促动效；页面滚动并聚焦第一个错误字段。用户修正字段后，对应警示立即消失。

动效只用于帮助定位错误，不依赖颜色表达，并在 `prefers-reduced-motion: reduce` 下关闭位移动画。校验失败时不向服务端提交请求。

## 当前位置

当前线上地址为 HTTP 裸 IP，浏览器不会在该环境开放定位 API。保留“使用当前位置”按钮：

- 非安全上下文点击后提示“当前位置功能等待域名申请及 HTTPS 配置，请先手动搜索出发地”。
- 安全上下文继续使用现有浏览器定位和服务端逆地理编码流程。
- 保留定位权限拒绝、超时和一般失败的不同提示。

域名和 HTTPS 配置不属于本次代码改动范围。

## 数据兼容

已有预设偏好和“不限”保持有效。旧活动载入时不迁移或删除历史偏好。修改后的服务端同时校验预设选项和自定义偏好，避免只改前端造成绕过。

## 验证

- 三种活动类型只显示各自确认后的偏好列表。
- 选择“其他”后显示输入框，空值和超过 20 个字均不能保存。
- 每个无效字段独立显示警示，修正后立即清除，首次提交聚焦第一个错误字段。
- HTTP 环境点击当前位置显示等待域名与 HTTPS 的提示，不调用定位 API。
- 现有语法检查和完整测试继续通过；新增业务规则与接口测试覆盖自定义偏好。
