# 活动退出按钮设计

## 目标

在活动详情页现有的“邀请伙伴 / 管理活动”操作区增加清晰可见的“退出活动”入口，让普通成员可以直接退出，也让发起者明确知道需要先移交权限。

## 界面位置

- “退出活动”与“邀请伙伴”“管理活动”位于同一操作区。
- 按钮使用现有的危险操作文字样式，不改变“邀请伙伴”的主按钮层级。
- 桌面端横向排列；空间不足和手机端允许自然换行，按钮不能因屏幕比例而消失。
- 发起者和普通成员都显示该入口。

## 交互规则

### 普通成员

1. 点击“退出活动”。
2. 弹出二次确认，说明退出后将失去该共享活动的成员访问权限。
3. 点击“确认退出”后执行现有退出操作，并返回活动目录。

### 发起者

1. 点击“退出活动”。
2. 不直接执行退出；弹窗说明“发起者需要先移交发起权限才能退出”。
3. 弹窗提供“再想想”和“前往管理活动”。
4. 点击“前往管理活动”后打开现有活动管理弹窗，由发起者选择接任成员。

### 当前不能退出

- 投票期间、活动暂停或其他现有业务规则不允许退出时，入口保持可见。
- 点击后以明确文案说明不能退出的原因，不使用无说明的禁用按钮。

## 范围

- 复用现有 `leave`、确认弹窗和活动管理流程。
- 不修改服务端退出规则，不新增自动移交，不建立新的完整活动菜单。
- 不调整邀请、成员移除、取消活动等其他管理功能。

## 验收标准

1. 活动详情操作区可以在桌面端和手机端看到“退出活动”。
2. 普通成员需要二次确认后才能退出，并在成功后返回活动目录。
3. 发起者不能直接退出，可以从提示弹窗进入活动管理并完成权限移交。
4. 投票期间等受限状态会显示具体原因。
5. 原有邀请伙伴、管理活动和退出接口行为不受影响。
