# MeetPoint 暖色玻璃工作台设计

## 目标

将 MeetPoint 内部工作台改造成暖色渐变背景上的玻璃化任务界面。设计参考用户提供的工作台截图所体现的层级：悬浮胶囊导航、大块圆角功能区、少量深色对比区和明确的当前状态；不复制发票产品的内容结构。

本次覆盖四个工作页面：我的活动、集合点推荐、成员与需求、意见反馈。相聚日历保留现有内容与插画，仅统一工作台导航和外层背景。Landing Page、登录注册、接口协议、地图、投票和身份逻辑不在本次功能改动范围内。

## 视觉系统

- 背景使用米白到浅杏色的底层渐变，并在右上、左下布置低饱和橙粉光晕。
- 工作台在桌面端形成距窗口四周留白的悬浮容器；外层圆角 32px，主要区域 24px，按钮与表单 14–18px。
- 面板使用半透明暖白、细白边、适度背景模糊和柔和阴影。毛玻璃用于表达层级，不覆盖所有小元素。
- 深炭色用于顶部胶囊导航和推荐页的投票操作区，形成稳定的视觉锚点。
- 橙粉渐变只用于当前导航、主要按钮、投票进度、选中候选和地图汇聚点。
- 操作字体使用清晰的无衬线字体；数字使用等宽数字特性。工作台不使用大面积宋体标题。

## 全局框架

顶部保留 MeetPoint 品牌、中间胶囊导航和右侧身份入口。导航包含相聚日历、我的活动、集合点推荐、成员与需求、意见反馈。当前页面以橙粉渐变胶囊表示，其他栏目位于深炭色底上。

桌面端内容由两至四块大小不同的玻璃区域构成，避免均匀小卡片网格。手机端改为单列顺序，导航收进菜单，核心操作保持在首屏或拇指易触达区域。

## 页面结构

### 我的活动

- 主区域展示当前活动名称、时间、活动阶段和下一步操作。
- 右侧展示成员就绪、需求填写和投票概况。
- 下方以连续列表展示其他活动，保留创建活动、使用邀请码加入、进入活动和身份管理操作。
- 不新增无业务意义的统计指标。

### 集合点推荐

- 地图占主要宽度，成为页面视觉中心。
- 候选地点位于地图右侧，显示名称、区域、平均用时、票数和选中状态。
- 成员状态和投票进度进入下方深炭色操作区；确认、暂停、重新推荐等现有操作保持不变。
- 选择地图标记或候选地点继续打开现有地点详情与投票入口。

### 成员与需求

- 将现有成员表格放入宽幅玻璃面板，强化成员头像、出发地、交通方式、偏好、预算和状态的扫描顺序。
- 隐私状态、待填写和已就绪使用文字与图形共同表达，不只依赖颜色。
- 编辑需求、邀请伙伴和活动管理继续调用现有动作。

### 意见反馈

- 表单和历史记录组成两个不等宽的玻璃区域。
- 输入、错误和成功状态在对应区域内反馈，不增加新的全屏弹窗。
- 保持当前本地保存事实与说明，不制造后端已接入的假象。

### 相聚日历

- 保留现有日历、手账卡片和插画结构。
- 仅接入新的背景、顶部导航、外层圆角和基础控件样式，避免破坏已完成的视觉内容。

## 交互与状态

- 悬停和键盘聚焦需清晰；焦点环使用橙色且不被圆角容器裁切。
- 页面切换采用 180–240ms 的轻微淡入和位移，只表达状态变化。
- 毛玻璃在不支持 `backdrop-filter` 的浏览器中退化为不透明暖白面板。
- 加载使用局部骨架；空状态说明下一步；错误信息说明问题和恢复动作。
- `prefers-reduced-motion` 下关闭非必要动画。

## 数据与代码边界

页面继续使用 `app.js` 现有状态、`data-action` 事件和 API 调用。改造以 HTML 模板结构调整与 `layout.css` 样式为主，不改变活动、推荐、投票、成员、隐私和账号的数据模型。

避免为单次视觉改造引入新框架或依赖。可添加少量纯展示辅助函数，但不得复制业务状态或形成第二套事件系统。

## 验收标准

- 四个工作页面具有统一的暖色渐变、玻璃材质、圆角层级和胶囊导航。
- 桌面端 1440px 与手机端 390px 均无横向溢出、遮挡或不可达操作。
- 地图、候选选择、投票、成员需求、反馈、身份和导航按钮保持可用。
- 文字对比度、键盘焦点和 reduced-motion 行为可用。
- `node --check app.js` 通过；现有自动化测试除已知的实时推荐环境失败外不新增失败。
- 实际浏览器中检查“我的活动”和“集合点推荐”桌面与手机布局，并批量修正视觉问题后再交付。
